# Полка

Каталог товаров с добавлением через Telegram-бота. Администратор отправляет фотографию с названием в подписи, бот передаёт данные в API. Название и ключ изображения сохраняются в PostgreSQL, фотография - в MinIO. Каталог доступен в браузере и как Telegram Mini App без авторизации.

## Стек

| Сервис | Технологии |
| --- | --- |
| API | Python 3.12, FastAPI, SQLAlchemy 2, asyncpg, Alembic, boto3 |
| Бот | Python 3.12, aiogram 3, FastAPI webhook, HTTPX |
| Каталог | Next.js 16 App Router, React 19, TypeScript, CSS Modules |
| Хранилища | PostgreSQL 16, MinIO S3 |
| Инфраструктура | Docker Compose, Nginx |

## Устройство

```text
Telegram -> Nginx -> bot -> api -> PostgreSQL
                              -> MinIO

Браузер / Mini App -> Nginx -> web -> api
                          -> api -> изображение из MinIO
```

Nginx направляет `/api/` в API, `/telegram/webhook` в бот, остальные пути в Next.js. Между контейнерами используются имена сервисов Docker. API, бот и web по умолчанию запускаются в двух экземплярах.

- [API](apps/api/README.md) - создание товаров, хранение и выдача изображений.
- [Бот](apps/bot/README.md) - команды, обработка сообщений и webhook.
- [Web](apps/web/README.md) - каталог и интеграция с Telegram.
- `apps/infra/nginx/` - маршрутизация и балансировка.
- `scripts/start.py` - сборка, запуск и регистрация webhook.

## Требования

- Docker с Linux-контейнерами и Docker Compose v2. Используемая версия Compose: 2.40.3.
- Python 3.12 для `scripts/start.py`. Скрипт использует только стандартную библиотеку.
- Токен Telegram-бота и числовой Telegram ID администратора.
- Публичный HTTPS-адрес, направленный на Nginx. Для локального запуска подходит Cloudflare Tunnel.

Python-зависимости сервисов и Node.js устанавливаются внутри образов. Для запуска через Compose устанавливать их на компьютер не требуется.

## Настройка

Клонировать репозиторий и скопировать `.env.example` в `.env` в корне проекта. Заполнить следующие значения:

| Переменная | Назначение |
| --- | --- |
| `TELEGRAM_BOT_TOKEN` | Токен бота, полученный в BotFather |
| `TELEGRAM_ADMIN_ID` | ID пользователя, которому разрешено создание товаров |
| `TELEGRAM_WEBHOOK_SECRET` | Секрет webhook, не менее 32 символов |
| `API_SERVICE_TOKEN` | Сервисный ключ создания товаров, не менее 32 символов |
| `MINI_APP_URL` | Полный публичный HTTPS-адрес каталога с путём `/catalog` |
| `POSTGRES_PASSWORD` | Пароль PostgreSQL |
| `MINIO_ROOT_USER`, `MINIO_ROOT_PASSWORD` | Учётные данные MinIO |
| `S3_ACCESS_KEY`, `S3_SECRET_KEY` | Для локальной конфигурации совпадают с пользователем и паролем MinIO |

Для генерации каждого из двух независимых секретов можно выполнить:

```text
python -c "import secrets; print(secrets.token_hex(32))"
```

`MINIO_ROOT_USER` должен содержать не менее 3 символов, `MINIO_ROOT_PASSWORD` - не менее 8. При изменении учётных данных MinIO нужно согласованно изменить S3-ключи API. PostgreSQL использует пароль первоначальной инициализации volume; изменение `.env` само по себе не меняет пароль существующей роли.

Основные адреса и параметры:

| Параметр | По умолчанию |
| --- | --- |
| `PROXY_HOST_PORT` | `8080` |
| `POSTGRES_HOST_PORT` | `5432`; при конфликте можно указать `5433` |
| `S3_BUCKET_NAME` | `catalog-images` |
| `REPLICAS_COUNT_API` | `2` |
| `REPLICAS_COUNT_BOT` | `2` |
| `REPLICAS_COUNT_WEB` | `2` |

Для приложений указывается положительное количество реплик. Сервис миграций запускается в одном экземпляре. В Compose внутренние адреса PostgreSQL, MinIO и API заданы отдельно от локальных значений `.env`: `postgres:5432`, `http://minio:9000`, `http://api:8000`.

## Запуск с Telegram

Все команды выполняются из корня проекта. В отдельном терминале запустить туннель на порт Nginx:

```text
cloudflared tunnel --url http://127.0.0.1:8080
```

Туннель может получить адрес до запуска приложений. В Windows исполняемый файл может называться `cloudflared.exe`. Оставить процесс работающим и записать выданный адрес в `.env`:

```dotenv
MINI_APP_URL=https://your-domain.trycloudflare.com/catalog
```

Если изменён `PROXY_HOST_PORT`, указать тот же порт в команде туннеля.

Запустить окружение:

```text
python scripts/start.py
```

Скрипт проверяет Compose, собирает образы, запускает сервисы и регистрирует webhook. PostgreSQL и MinIO должны перейти в `healthy`, миграции должны успешно завершиться, затем запускаются приложения и Nginx. API самостоятельно создаёт бакет, если его ещё нет.

Адрес webhook формируется из протокола и домена `MINI_APP_URL` с заменой пути на `/telegram/webhook`. Например:

```text
Каталог: https://your-domain.trycloudflare.com/catalog
Webhook: https://your-domain.trycloudflare.com/telegram/webhook
```

После смены временного адреса туннеля обновить `MINI_APP_URL` и повторить запуск скрипта. Обновления бота принимаются через webhook, polling не используется.

## Локальный запуск без регистрации webhook

После заполнения `.env`:

```text
docker compose up --build --wait --wait-timeout 120
```

Команда запускает окружение в фоне, но не регистрирует webhook. Все обязательные настройки бота всё равно должны быть заполнены; для проверки только браузера `MINI_APP_URL` может оставаться адресом из шаблона.

- Каталог: http://127.0.0.1:8080/catalog
- Список товаров: http://127.0.0.1:8080/api/v1/products
- Консоль MinIO: http://127.0.0.1:9001

Адрес каталога меняется вместе с `PROXY_HOST_PORT`. Порты API, бота и Next.js отдельно на компьютер не публикуются. PostgreSQL и MinIO опубликованы только на loopback для локальных инструментов.

## Команды

```text
docker compose ps -a
docker compose logs --tail 100 api bot web proxy migrate
docker compose exec proxy nginx -t
docker compose exec --index 1 api python -m alembic -c alembic.ini current
```

У сервиса `migrate` ожидается `Exited (0)`. PostgreSQL, MinIO и каждая реплика приложений должны быть `healthy`; Nginx - `running`. Эндпоинты приложений `/health` проверяют HTTP-ответ, но не выполняют непрерывную проверку внешних зависимостей.

Управление общим webhook:

```text
docker compose exec --index 1 bot python manage_webhook.py status
docker compose exec --index 1 bot python manage_webhook.py set
docker compose exec --index 1 bot python manage_webhook.py delete
```

Для другого адреса доступен `set --url "https://example.com/telegram/webhook"`. Удаление webhook сохраняет накопившиеся обновления. Остановка отдельной реплики webhook не удаляет.

Повторное применение миграций без запуска API:

```text
docker compose run --rm migrate
```

Миграции запускаются отдельным сервисом; API ждёт его успешного завершения. После изменения количества реплик в `.env` применить конфигурацию:

```text
docker compose up -d --wait
```

## Проверки

### Основной сценарий

1. Отправить `/start` в личном чате с ботом и открыть каталог кнопкой.
2. С аккаунта администратора выбрать «Создать товар» или отправить `/create`.
3. Отправить одну фотографию с названием в подписи, без режима отправки документом.
4. Получить подтверждение с ID товара, заново открыть каталог в Telegram и браузере.
5. Проверить, что название и фотография отображаются.
6. С другого аккаунта отправить `/create` и фотографию: товар не должен создаваться.

Поддерживаются JPEG и PNG до 5 МиБ, название - от 1 до 255 символов после проверки. Обработчик работает без FSM: фотография с подписью от администратора принимается независимо от предварительного вызова `/create`. На обычное обращение бот отвечает «У меня есть товар» и предлагает каталог.

### Защита и повторное создание

В Windows для следующих команд использовать `curl.exe` вместо `curl`.

Без секрета webhook ожидается `403`:

```text
curl -i -X POST http://127.0.0.1:8080/telegram/webhook -H "Content-Type: application/json" -d "{}"
```

Создание через API без `X-Service-Token` также должно вернуть `403`. Для проверки повторов подготовить `product.jpg`, подставить сервисный ключ и выполнить запрос дважды:

```text
curl -X POST http://127.0.0.1:8080/api/v1/products -H "X-Service-Token: YOUR_SERVICE_TOKEN" -F "title=Test product" -F "source_chat_id=-9000000000000000" -F "source_message_id=1" -F "photo=@product.jpg"
```

Ожидаются ответы `200` с одинаковым ID. Повтор с теми же chat/message не меняет исходный товар. Для конкурентной проверки отправить тот же запрос одновременно из нескольких терминалов: ID должен совпасть во всех успешных ответах, а в каталоге должен остаться один товар для этой пары. Сама проверка создаёт товар в каталоге; для нового независимого прогона использовать другой `source_message_id`.

### Реплики и сохранность данных

1. Несколько раз запросить `/api/v1/products`, `/catalog` и webhook без секрета.
2. В `docker compose logs --tail 100 proxy` проверить разные адреса `upstream` для одного маршрута.
3. Получить имена контейнеров через `docker compose ps` и остановить только один экземпляр командой `docker stop CONTAINER_NAME`.
4. Повторить обращения: оставшаяся реплика должна продолжить обработку. При отказе возможны задержки и временные ошибки; повтор webhook выполняет Telegram.
5. Восстановить экземпляр командой `docker start CONTAINER_NAME`.
6. Выполнить `docker compose down`, затем `docker compose up --build --wait --wait-timeout 120`. Ранее созданные товары и изображения должны сохраниться.

`docker compose stop api` останавливает все API-реплики, поэтому для проверки одного экземпляра используется его имя. После повторного запуска контейнера нужно дождаться его готовности и обновления DNS в Nginx.

## Логи и остановка

Логи API и бота выводятся в stdout и по умолчанию пишутся в volumes `api_logs` и `bot_logs`. Файлы разделены по hostname экземпляров. Для каждой такой директории сохраняется до 5 файлов по 10 МиБ, включая текущий. Параметры задаются через `LOG_TO_FILE`, `LOG_MAX_BYTES`, `LOG_MAX_FILES`. Каталоги старых экземпляров автоматически не удаляются.

Перед завершением локальной Telegram-сессии удалить webhook, затем остановить туннель:

```text
docker compose exec --index 1 bot python manage_webhook.py delete
docker compose down
```

`down` сохраняет именованные volumes. `down -v` удаляет их вместе с товарами, фотографиями и файловыми логами.

## Ограничения

- PostgreSQL, MinIO и Nginx запущены в одном экземпляре. Реплики приложений не обеспечивают отказоустойчивость хранилищ, прокси или самого Docker-хоста. Volumes не заменяют резервные копии.
- Используется сторонняя сборка MinIO `derklaro/minio:RELEASE.2025-10-15T17-29-55Z`, а не официальный образ. В её составе недоступны curl/wget, а mc не запускается на проверенной платформе; healthcheck использует Bash и HTTP readiness endpoint.
- PostgreSQL и S3 не имеют общей транзакции. При ошибке загрузки запись БД откатывается; после успешной загрузки и неуспешного или неоднозначного commit в S3 может остаться невостребованный объект. Автоматическая очистка таких объектов не реализована.
- Идемпотентность создания определяется парой chat/message, ограничениями UNIQUE и детерминированным ключом изображения. Подтверждение отправляется после commit; ошибка отправки ответа не удаляет товар. При повторной доставке ответное сообщение бота может дублироваться.
- Изображения проверяются по размеру и сигнатуре JPEG/PNG, без полного декодирования. API возвращает изображение целиком в памяти.
- Временный HTTPS-туннель работает, пока запущен его процесс. При новом адресе требуется обновление настроек и регистрации webhook.
- Администратор проверяется ботом по Telegram user ID. API создания доверяет сервисному ключу; его обладатель может создавать товары напрямую.
