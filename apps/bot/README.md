# Telegram-бот

aiogram 3 с HTTP webhook на FastAPI. Принимает команды и сообщения Telegram, скачивает фотографии и передаёт multipart-запрос в API. Напрямую к PostgreSQL и MinIO не обращается.

## Структура

- `app/routers/` - защищённый вход `/telegram/webhook` и `/health`.
- `app/dispatcher.py` - порядок подключения обработчиков.
- `app/handlers/` - `/start`, `/help`, `/create`, фотографии и обычные обращения.
- `app/keyboards/` - кнопки каталога и создания товара.
- `app/clients/` - HTTP-клиент API каталога.
- `app/schemas/` - модель ответа API.
- `app/core/` - настройки и логирование.
- `manage_webhook.py` - регистрация, проверка и удаление общего webhook.

## Обработка

- `/start` предлагает открыть Mini App, `/help` перечисляет команды.
- «Создать товар» и `/create` выдают инструкцию администратору.
- Фото и название принимаются одним сообщением, название берётся из caption.
- Доступ проверяется по `message.from_user.id`, до скачивания и HTTP-запроса.
- FSM не используется: предварительная команда создания не обязательна, состояние между сообщениями не хранится.
- Webhook проверяет Telegram secret token и ожидает завершения `dispatcher.feed_update`. Необработанные временные ошибки не преобразуются в успешный HTTP-ответ.
- Один webhook обслуживается всеми репликами. Его регистрация и удаление не привязаны к lifespan отдельного экземпляра.

Bot и AsyncClient создаются на процесс, клиент API использует сервисный ключ. При повторной доставке API возвращает уже созданный товар по исходным chat/message; повторное подтверждение в чате возможно.

Запуск, HTTPS, команды `manage_webhook.py` и проверки приведены в [главном README](../../README.md).
